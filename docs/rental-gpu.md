# 租用服务器配置与计费前检查

**当前没有实测训练显存或 GPU 小时数。** 参数量 515M 不代表任何 24 GiB 卡都能完成微调；T5、VAE、激活、音频长度和评测模型会增加占用。

初始租机目标：Linux x86_64、单张 NVIDIA CUDA GPU、至少 24 GiB 显存、32 GiB 系统内存、8 vCPU、100 GiB 可用 SSD。优先选可中断计费且能保留磁盘快照的实例。若 24 GiB 发生 OOM，再试 48 GiB 单卡；若仍超限，先缩短片段或缓存 VAE 潜变量，并在基线和改进版中同步调整。作者代码默认 30 秒片段、双 GPU，不能直接套用本项目的单卡预算。

本仓库使用 PyTorch 2.4、Transformers 4.44、Diffusers 0.30 对应的上游依赖；环境建议 Python 3.11，NVIDIA 驱动需兼容所安装的 CUDA 版 PyTorch。`bf16` 仅用于支持的 GPU；不支持时将两份训练配置统一改为 `fp16` 并重新运行显存探针。

上机顺序：

1. `nvidia-smi` 查看 GPU 型号、显存、驱动及是否有其他进程。
2. 安装依赖、放入已审查数据；记录原始录音数、处理后样本数及磁盘占用。
3. 运行 README 中的 VAE 回环探针，再分别运行两步基线与改进训练。
4. 根据 `train.jsonl` 的 `elapsed_s` 与 `peak_vram_gb` 估计 1000 步总 GPU 小时；训练中的首次模型下载/初始化时间单列，不混入单步吞吐估算。
5. 保存租用平台报价、GPU 型号、显存、磁盘规格、步数和最终实际费用。评测 CLAP/FAD 另计时间。

以相同训练步数而非相同 wall time 对照方法；额外循环模块的时间开销应单独报告。若 GPU 不支持指定精度或依赖安装失败，先排查环境，再改训练参数。
